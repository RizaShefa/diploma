# Breast Ultrasound Classification — Academic Research Prototype

A CNN-based classifier for breast ultrasound images (benign vs malignant), with
explainability, a reproducible experiment pipeline and a Flask web interface.

> **This is an academic research prototype.** It is not a medical device, has not
> been clinically validated, and must not be used for diagnosis or treatment
> decisions. No regulatory compliance (HIPAA, GDPR, FDA, CE) is claimed or
> implemented.

## What this system does

```
Ultrasound image
      ↓
Validation            magic-byte check, size cap, decode check
      ↓
Preprocessing         SHARED between training and serving
      ↓
CNN                   custom / ResNet50 / EfficientNet-B0
      ↓
Prediction            label + probability + confidence band
      ↓
Grad-CAM              class-discriminative attention heatmap
      ↓
Structured report     model card, validated metrics, limitations, disclaimer
```

Alongside the application there is a reproducible research pipeline that
produces every figure and table from saved experiment output:

| Page | What it shows |
|---|---|
| `/service` | Upload → prediction → confidence → Grad-CAM → structured report |
| `/dataset` | Class distribution, integrity audit, split composition, shortcut check |
| `/research` | Test metrics with 95% CIs, model comparison, error analysis |
| `/history` | Local log of predictions made through the prototype |

**Nothing is displayed that was not generated by a real run.** Sections without
results render “Experiment not yet executed” together with the command that
would produce them.

## Architecture

```

configs/                    JSON experiment configs; model configs inherit base.json
  base.json                 shared data/training/evaluation settings
  custom_cnn.json           the thesis's architecture at 224x224
  custom_cnn_legacy64.json  faithful reproduction of the original 64x64 model
  resnet50.json             ImageNet-pretrained ResNet50
  efficientnetb0.json       ImageNet-pretrained EfficientNet-B0
src/
  config.py                 config loading + global seeding
  preprocessing.py          SINGLE SOURCE OF TRUTH for image preprocessing
  augmentation.py           training-split-only augmentation
  data/
    loader.py               dataset discovery and manifest
    integrity.py            duplicate / near-duplicate detection, leakage measurement
    splitting.py            group-aware stratified train/val/test splitting
    analysis.py             dataset statistics and figures
  models/registry.py        architectures + Grad-CAM target layers
  training/trainer.py       training orchestration
  evaluation/
    metrics.py              metrics + bootstrap CIs + calibration + thresholds
    plots.py                figure generation
    errors.py               error analysis
  explainability/gradcam.py Grad-CAM
  inference/
    validation.py           upload validation
    predictor.py            model registry + inference
    history.py              prediction history (SQLite)
  reporting/
    report.py               structured report
    results_index.py        loads saved results for the dashboard
scripts/                    prepare_data, analyze_dataset, train, evaluate, compare_models
tests/                      97 tests
models/                     trained artifacts + metadata (gitignored)
results/                    metrics, figures, split (gitignored)
```

### Why preprocessing is a single module

The original implementation preprocessed images differently in training and
serving:

| | training (`MainTrain.py`) | serving (`app.py`) |
|---|---|---|
| BGR → RGB | yes | **no** |
| normalisation | yes | **no** |

Measured on 150 held-out images with the shipped model, that skew **flipped
9/150 predictions (6.0%)**. Both paths now call `src.preprocessing.preprocess_array`,
and a model's profile is recorded in its metadata at training time and replayed
at inference. `tests/test_preprocessing.py` asserts the two paths produce
bit-identical output.

## Dataset setup

This project uses **BUSI** (Breast Ultrasound Images Dataset):

> Al-Dhabyani W, Gomaa M, Khaled H, Fahmy A. *Dataset of breast ultrasound
> images.* Data in Brief. 2020 Feb;28:104863. doi:10.1016/j.dib.2019.104863

780 images — 437 benign, 210 malignant, 133 normal — with lesion masks.

1. Download it (Kaggle: “Breast Ultrasound Images Dataset”, or the authors' page).
2. Extract it anywhere.
3. Ingest it:

```bash
python scripts/prepare_data.py --source "C:/Downloads/Dataset_BUSI_with_GT"
```

This copies images into `data/busi/{benign,malignant,normal}/` and writes a
manifest recording provenance and per-class counts. Originals are not modified.

### Why not the previous dataset

The 5,000-image set previously used here was a **pre-augmented derivative**, not
an original collection. Measured by `src/data/integrity.py`:

| Measure | Value |
|---|---|
| Exact byte-duplicate groups | 51 (103 files) |
| Images with a near-twin (corr > 0.95) | 2,053 / 2,500 (82.1%) |
| Distinct source clusters | ~891, not 2,500 |
| **Test images with a near-duplicate in train** | **77.3%** |

Because augmentation preceded the split, roughly three quarters of the test set
had been seen in training. That is the mechanism behind the originally reported
99.6% accuracy. BUSI removes the problem at its root and matches the citation
the thesis already uses.

Expect honest accuracy in the **80–90%** range. That is the correct number.

## Reproducing the results

Run in order. Each step prints the next one.

```bash
# 1. Dataset analysis, integrity audit, and the shared split
python scripts/analyze_dataset.py
python scripts/analyze_dataset.py --legacy-dataset   # also audit the old dataset

# 2. Train (all models read the SAME split from results/split.json)
python scripts/train.py --config custom_cnn
python scripts/train.py --config resnet50
python scripts/train.py --config efficientnetb0

# 3. Evaluate on the held-out test split
python scripts/evaluate.py --model custom_cnn
python scripts/evaluate.py --model resnet50
python scripts/evaluate.py --model efficientnetb0

# 4. Build the comparison table and figures
python scripts/compare_models.py
```

Ablations:

```bash
# Augmentation: does it help?
python scripts/train.py --config custom_cnn --no-augmentation
python scripts/evaluate.py --model custom_cnn_noaug

# Resolution: 64x64 (the original) vs 224x224
python scripts/train.py --config custom_cnn_legacy64
python scripts/evaluate.py --model custom_cnn_legacy64
```

### What makes the comparison fair

Every model inherits `configs/base.json`, so optimiser, learning rate, batch
size, callbacks, class weighting, augmentation policy, seed and split are
identical. Only the architecture and its required preprocessing profile differ.
`compare_models.py` re-checks this from the saved metadata and prints a warning
if any controlled setting diverged.

### Reproducibility

- Seeds are set for Python, NumPy and TensorFlow from `config["seed"]`.
- The split is written to `results/split.json` and reused; `train.py` refuses to
  run against a stale split.
- Each model saves `<name>.metadata.json` recording its full config, environment
  (Python/TF versions, platform), epochs run, class weights and split sizes.

CPU training is deterministic. Exact GPU reproducibility additionally requires
`TF_DETERMINISTIC_OPS=1` before TensorFlow initialises, which `set_global_seeds`
sets but cannot guarantee if TF is already imported.

## Running the web application

```bash
python app.py
# http://127.0.0.1:5000
```

The app serves the newest non-legacy model. If none has been trained, it falls
back to `BreastCancer10Epochs.h5`, labels it **legacy**, and attaches this
warning to every prediction:

> This model was trained on a dataset with substantial train/test overlap (77.3%
> of test images had a near-duplicate in training). Its reported 99.6% accuracy
> is not a valid generalisation estimate.

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/predict` | **Original endpoint, preserved.** Returns plain text |
| `POST` | `/api/predict` | JSON report: classification, confidence, Grad-CAM, limitations |
| `GET` | `/api/models` | Registered models and their metadata |
| `GET` | `/api/results` | Saved experiment output for the dashboard |
| `GET` | `/api/history` | Prediction history + summary |
| `POST` | `/api/history/clear` | Delete all history |
| `GET` | `/api/report/<id>.txt` | Plain-text report for a stored prediction |
| `GET` | `/api/health` | Health check |

`POST /api/predict` — multipart form, field `file`; optional `model`, `explain=0`.

```jsonc
{
  "classification": {
    "label": "malignant",
    "statement": "The model classified this image as malignant with a predicted probability of 87.3%.",
    "probabilities": { "benign": 0.127, "malignant": 0.873 },
    "decision_threshold": 0.35
  },
  "confidence": { "value": 0.873, "band": "high", "calibrated": false, "note": "..." },
  "model": { "name": "resnet50", "validated_performance": { "sensitivity": "0.91 [0.85-0.96]" } },
  "explanation": { "method": "Grad-CAM", "overlay_png": "data:image/png;base64,...", "disclaimer": "..." },
  "limitations": [ "..." ],
  "disclaimer": "This is an academic research prototype..."
}
```

Errors return `{"error": "...", "error_type": "validation|model_unavailable|inference"}`
with an appropriate status. Stack traces are logged server-side, never returned.

## Configuration

Environment variables (all optional):

| Variable | Default | Purpose |
|---|---|---|
| `BCD_MODEL_NAME` | newest non-legacy | Which model to serve |
| `BCD_STORE_IMAGES` | `0` | `1` stores thumbnails in history |

Experiment settings live in `configs/*.json`. Model configs override only what
differs from `base.json`.

## Explainability

**Grad-CAM** (Selvaraju et al., 2017) weights the final convolutional feature
maps by the gradient of the target class score. It was chosen over SHAP and LIME
because it answers the question that matters for ultrasound — *did the model
look at the lesion, or at the depth ruler, burned-in scanner text, or
background?* — in a single backward pass. LIME's superpixel segmentation is
unstable on speckle texture; KernelSHAP is prohibitively slow and DeepSHAP's
pixel attributions are noisy on low-contrast grayscale.

**Resolution caveat.** The heatmap's precision is bounded by the final feature
map, not the display size:

| Model | Input | Feature map | Cells |
|---|---|---|---|
| legacy (shipped `.h5`) | 64×64 | 6×6 | 36 — too coarse to be meaningful |
| custom_cnn | 224×224 | 52×52 | 2,704 |
| ResNet50 / EfficientNet-B0 | 224×224 | 7×7 | 49 |

Every response reports `feature_map_size` and a plain-language note, so the
limitation is stated rather than hidden.

**The heatmap is not a segmentation.** It visualises model attention. It is not
a lesion boundary and is not medically validated. The API and UI both say so.

`gradcam.mask_agreement()` can score a heatmap against BUSI's ground-truth lesion
masks (pointing-game hit and IoU). It is available for offline analysis and is
**not** wired into the prediction endpoint, since uploaded images have no mask.

## Security and privacy

Implemented:

- Magic-byte format verification (extensions are not trusted)
- Upload size cap, enforced both by Flask and in the validator
- Decode and dimension checks (rejects corrupt files and decompression bombs)
- Uploads are **not written to disk** by the API path
- `debug=False` by default
- Errors return safe messages; details go to the server log only
- Figure serving is constrained to `results/figures` (path traversal blocked)
- History stores **metadata only**; image retention is opt-in and thumbnail-only

**Not implemented — do not claim otherwise:** authentication, authorisation,
transport encryption (HTTPS), audit logging, data-retention policy, encryption
at rest, or any regulatory compliance. This prototype is intended to run locally.

## Known limitations

- Binary benign/malignant only. BUSI's `normal` class is excluded by default
  (`data.include_normal` in `configs/base.json`).
- Single public dataset; generalisation to other scanners, settings and
  populations is untested.
- No clinical metadata (age, scanner, BI-RADS), so no subgroup or fairness
  analysis is possible on this data. Stated as future work rather than attempted.
- Probabilities are raw softmax outputs and are **not calibrated**. ECE is
  reported so the degree of miscalibration is visible.
- `pred/` (546 mixed-format files) is retained from the original project and is
  not part of any experiment; it carries no labels.
- A stray `README.mdgit` from an earlier commit remains in the repository and
  can be deleted.
